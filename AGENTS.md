# Install and open Creator Source Graph in the current AI host

When the user gives this repository URL to Codex or Claude Code and asks to install and open it, complete that workflow in the current subscribed host session. Do not ask the user to copy a task into another AI window or start a separate provider/API session for initial installation.

1. Read the public README and obtain the app in a persistent local folder. Use the release package matching this machine when Node is not available; bundled packages include `runtime/node` (`runtime/node.exe` on Windows). If using a source checkout with Node 20 or newer already available, `node` is sufficient. Preserve an existing installation and local account data. Verify release downloads against their `SHA256SUMS`; do not execute unrelated downloads or install a provider SDK.
2. Use the runtime from that app folder and run one setup command for the host currently doing this work:

   ```sh
   ./runtime/node cli.mjs setup --host codex
   ./runtime/node cli.mjs setup --host claude
   ```

   Choose one command. For source installations, replace `./runtime/node` with `node`; on Windows use `runtime\node.exe`. If the user also supplied a product/repository target to research, append that target URL. The repository URL used to install this app is not automatically a research target. Quote paths and URLs with the host shell's appropriate quoting; do not interpolate webpage text into commands. Run from the app folder, or use absolute runtime/CLI paths.
3. Setup installs the personal host skill, launches/reuses the local app and opens its graph or Agentlas sign-in page. An identical generated skill is reused without rewriting it. A different or modified skill is preserved and causes a clear collision error; inspect the exact conflict and obtain explicit replacement authorization before using `--force`. Use `--skills-dir <parent>` only when the user requested a custom installation location.
4. Read the installed `SKILL.md` path in the setup receipt immediately, so this same host session can continue without requiring a restart or a second invocation. The installed helper uses the bundled runtime and works from other project directories. Do not infer that installation itself performs web research.
5. If setup returns `loginRequired`, tell the user to sign in on the opened Agentlas page and preserve any `intendedProductUrl`. Poll the installed helper's `login status` without reopening login. Pause web research until `authenticated: true`. Never ask for passwords, inspect browser cookies, copy tokens or bypass login. When authenticated, resume the same target; preserve the exact run ID if setup already created one.
6. If a target URL is present, follow the installed skill now using this host's own search/browser tools: discover relevant and similar content on Instagram, YouTube, X and Threads, observe views where visible, and trace evidence-supported intermediate/earliest-found sources. Derive roughly 6–10 grounded keyword angles from the opened target to broaden related social-content discovery; optional product.keywords preserves up to 16 keywords for analysis chips. Derive up to six prioritized suggestions tied to the original target, distinguishing actual publication channels from reference-only originals. A project homepage, repository or paper, including LangGraph, is a reference source rather than an automatic distribution entry. For a publication suggestion, name an actual submission/publication route accepting new posts, launches, listings or tips; open its public rules and its discoverable feed/index, and provide the placement metadata required by the current import schema. Community Show HN, launch-directory or newsletter-tip routes are possible examples only after their route, rules and discovery surface are verified. Do not claim these channels supplied the traced creator posts without evidence. Suggestions lacking verified placement metadata remain reference-only. The target’s own GitHub/docs provide durable product evidence and are separate from external channel placement. Support the compact brand → publication channel → possible AI collector → social creator route with opened evidence, keeping collection and downstream discovery hypothetical. Do not imply eligibility, acceptance, creator AI use or visibility probability is proven or guaranteed. Import truthful findings and suggestions into the exact local run, then verify the overall content/source graph and suggestion priorities. Suggestions remain for the user to review; do not execute or publish them automatically. Without a target, leave the signed-in graph open and ask for the product/repository URL to research. Do not invent a default target or mark research complete from sample data.

The initial installation workflow above continues in the current AI chat. After Agentlas sign-in, the browser opens a home screen with a centered target URL form. Submitting the form starts research and opens the analysis view. Back returns home for a new URL; View latest reopens the retained analysis. The analysis view’s editable target and Reanalyze control also launch a new local Codex or Claude Code CLI job, using an installed host signed in with an existing subscription. Auto selects an authenticated subscription host; missing or signed-out hosts produce an actionable error before replacing the previous result. This job does not automatically continue the installing chat. No provider API keys or separate provider billing are required.

Browser research jobs must actively trace explicit links, then investigate an evidence-supported inferred-candidate fallback when those paths are missing or incomplete. Open both endpoints and every supporting evidence page. Require distinctive content evidence and chronological context; search-only endpoints, snippets and generic similarity are insufficient. Submit only separately labelled low/medium-confidence candidates under the current import schema. If no candidate meets that standard, explain the missing evidence and submit none. Do not fabricate provenance or enforce a candidate-count target.

Browser jobs show progress and automatically import validated complete/partial results. Stop, sign-out and app shutdown abort the job; superseded or account-switched results must not import. Reanalysis creates a fresh run while preserving existing source records and run metadata, without offering historical graph restoration. Manual skill invocation and CLI run/import remain available. `/api/analyze` creates a ready run only; `/api/research` launches the installed host job.

The AI host’s subscription and tool limits apply. Agentlas login gates the local workspace and is separate from host subscription authentication. If the current host has no local shell access or cannot reach this machine’s loopback app, state that specific limitation without changing global account settings. Never inspect credential files or copy tokens to bypass missing host authentication.
